Confeitaria Lógica

Um sistema especialista que recebe pedidos de doces, confere o estoque, avisa sobre restrições alimentares e mostra como substituição, unificação e resolução fazem o computador "pensar".

1 · Contexto2 · Substituição3 · Unificação4 · Resolução

1Contexto

Uma confeitaria quer automatizar o atendimento: o sistema recebe pedidos, verifica se o doce pode ser produzido com o estoque e alerta quando o cliente tem restrição a algum ingrediente.

🍬 Doces: brigadeiro, torta de limão 🥛 Ingredientes: chocolate, leite condensado, limão 👩 Clientes: Ana, Bia

Predicados (as "perguntas" que o sistema sabe fazer)

Representação formal 
Pedido(cliente, doce)
Usa(doce, ingrediente)
Tem(ingrediente)
Restricao(cliente, ingrediente)
Produzivel(doce)
Aceito(cliente, doce)
Alerta(cliente, doce, ingrediente)
Em linguagem natural

Predicado é uma frase com lacunas que pode ser verdadeira ou falsa. Exemplo: Pedido(ana, brigadeiro) = "Ana pediu brigadeiro".

Restricao = alergia ou intolerância. Produzivel = temos tudo para fazer o doce.

Base de conhecimento

Prolog 
% Fatos
pedido(ana, brigadeiro).
pedido(bia, tortaLimao).
usa(brigadeiro, chocolate).
usa(brigadeiro, leiteCondensado).
usa(tortaLimao, limao).
usa(tortaLimao, leiteCondensado).
tem(chocolate).
tem(leiteCondensado).
tem(limao).
restricao(bia, leiteCondensado).

% Regras
produzivel(brigadeiro) :-
    tem(chocolate), tem(leiteCondensado).
produzivel(tortaLimao) :-
    tem(limao), tem(leiteCondensado).
aceito(C, D) :- pedido(C, D), produzivel(D).
alerta(C, D, I) :-
    pedido(C, D), usa(D, I), restricao(C, I).
Entendendo

Fatos são verdades já conhecidas: quem pediu o quê, o que cada receita leva e o que há no estoque. A Bia tem restrição a leite condensado.

Regras criam conhecimento novo. Lê-se o :- como "se":

• Um pedido é aceito se o doce é produzível.
• Há alerta se o cliente pediu um doce que leva um ingrediente a que ele tem restrição.

Letras maiúsculas (C, D, I) são variáveis: lacunas que podem ser preenchidas.

Mesma regra em lógica de primeira ordem

∀c ∀d ∀i ( Pedido(c,d) ∧ Usa(d,i) ∧ Restricao(c,i) → Alerta(c,d,i) )
∀c ∀d ( Pedido(c,d) ∧ Produzivel(d) → Aceito(c,d) )

2Substituição

Substituir é trocar variáveis por termos concretos. Escrevemos { variável/valor }.

Representação formal 
Regra: Pedido(c,d) ∧ Produzivel(d) → Aceito(c,d)

σ₁ = { c/ana, d/brigadeiro }

Resultado:
Pedido(ana,brigadeiro) ∧ Produzivel(brigadeiro)
   → Aceito(ana,brigadeiro)
Regra: Pedido(c,d) ∧ Usa(d,i) ∧ Restricao(c,i)
          → Alerta(c,d,i)

σ₂ = { c/bia, d/tortaLimao }
σ₃ = { i/leiteCondensado }

Resultado final:
Pedido(bia,tortaLimao) ∧ Usa(tortaLimao,leiteCondensado)
 ∧ Restricao(bia,leiteCondensado)
   → Alerta(bia,tortaLimao,leiteCondensado)
Em linguagem natural

Pense na regra como uma receita com espaços em branco. Substituir é preencher os espaços.

Com σ₁, a regra genérica vira um caso real: "se a Ana pediu brigadeiro e brigadeiro é produzível, então o pedido da Ana é aceito".

Com σ₂ e σ₃ preenchemos a regra de alerta em duas etapas e chegamos a: "a Bia pediu torta de limão, que leva leite condensado, e ela tem restrição a ele, então alerta!"

Substituição em Python:

def aplicar(termo, s):
    if isinstance(termo, tuple):
        return tuple(aplicar(t, s) for t in termo)
    return s.get(termo, termo)

aplicar(('Pedido','?c','?d'),
        {'?c':'ana','?d':'brigadeiro'})
# ('Pedido','ana','brigadeiro')

3Unificação

Unificar é achar uma substituição que deixa dois termos idênticos. A mais simples possível é o MGU (Most General Unifier, "unificador mais geral").

Representação formal 
Exemplo 1
Pedido(c,d)  ↔  Pedido(bia,tortaLimao)
MGU: μ = { c/bia, d/tortaLimao }

Exemplo 2
Usa(d,i)  ↔  Usa(tortaLimao,leiteCondensado)
MGU: μ = { d/tortaLimao, i/leiteCondensado }

Exemplo 3 (falha)
Pedido(ana,d)  ↔  Pedido(bia,tortaLimao)
ana ≠ bia  → NÃO unifica ✗
Em linguagem natural

É o "encaixe" entre uma regra e um fato, como peças de quebra-cabeça.

Exemplos 1 e 2: as lacunas da regra se encaixam nos fatos, então a regra pode ser usada.

Exemplo 3: o pedido é da Ana, mas o fato fala da Bia. Duas constantes diferentes nunca se igualam, então não há encaixe e a regra não vale para esse caso.

Algoritmo de unificação em Python

def var(t): return isinstance(t, str) and t.startswith('?')

def walk(t, s):
    while var(t) and t in s: t = s[t]
    return t

def unify(a, b, s=None):
    s = {} if s is None else s
    a, b = walk(a, s), walk(b, s)
    if a == b: return s
    if var(a): return {**s, a: b}
    if var(b): return {**s, b: a}
    if isinstance(a, tuple) and isinstance(b, tuple) and len(a) == len(b):
        for x, y in zip(a, b):
            s = unify(x, y, s)
            if s is None: return None
        return s
    return None   # constantes diferentes: falhou

unify(('Pedido','?c','?d'), ('Pedido','bia','tortaLimao'))
# {'?c': 'bia', '?d': 'tortaLimao'}
unify(('Pedido','ana','?d'), ('Pedido','bia','tortaLimao'))
# None

Cada variável é marcada com ?. O programa compara os termos um a um: se achar variável, anota a troca; se achar duas constantes diferentes, devolve None (falha).

4Resolução

Na resolução provamos algo por contradição: supomos que a conclusão é falsa e vemos se isso leva a um absurdo (a cláusula vazia □). Se levar, a conclusão é verdadeira.

Pergunta: a Bia precisa de algum alerta no pedido dela?

Cláusulas (forma normal) 
C1: ¬Pedido(c,d) ∨ ¬Usa(d,i) ∨ ¬Restricao(c,i)
      ∨ Alerta(c,d,i)
C2: Pedido(bia,tortaLimao)
C3: Usa(tortaLimao,leiteCondensado)
C4: Restricao(bia,leiteCondensado)
C5: ¬Alerta(bia,tortaLimao,i)   ← negação da pergunta
Em linguagem natural

Cláusula é uma lista de opções ligadas por "ou". ¬ significa "não".

C1 é a regra de alerta reescrita ("ou não pediu, ou não usa, ou não tem restrição, ou há alerta"). C2 a C4 são fatos. C5 é a nossa aposta contrária: "não existe alerta".

Passo a passo

1
C5 + C1, unificando Alerta(c,d,i) com Alerta(bia,tortaLimao,i): { c/bia, d/tortaLimao } 
C6: ¬Pedido(bia,tortaLimao) ∨ ¬Usa(tortaLimao,i) ∨ ¬Restricao(bia,i)
2
C6 + C2: o pedido da Bia existe, então esse pedaço some. 
C7: ¬Usa(tortaLimao,i) ∨ ¬Restricao(bia,i)
3
C7 + C3, com { i/leiteCondensado }: 
C8: ¬Restricao(bia,leiteCondensado)
4
C8 + C4: um diz "a Bia não tem restrição", o outro diz "tem". Contradição! 
C9: □  (cláusula vazia)

Chegamos ao absurdo, então a aposta "não há alerta" estava errada. Logo há alerta, e o valor que foi unificado em i mostra qual: leite condensado. 🎯

O mesmo raciocínio no Prolog

?- alerta(bia, D, I).
D = tortaLimao,
I = leiteCondensado.

?- aceito(C, D).
C = ana, D = brigadeiro ;
C = bia, D = tortaLimao.

?- alerta(ana, D, I).
false.

O Prolog faz exatamente isso por baixo dos panos: unifica, substitui e resolve até achar uma resposta ou esgotar as possibilidades. Para a Ana não há alerta, e por isso a resposta é false.

Resultado final

Ana → brigadeiro: ACEITO, sem alertas ✓
Bia → torta de limão: ACEITO, mas com
      ALERTA: leite condensado ⚠

Substituição prepara a regra, unificação encontra o encaixe e resolução prova a conclusão.
